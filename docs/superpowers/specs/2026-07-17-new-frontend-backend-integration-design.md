# 新前端完整迁移与后端联调设计

**日期：** 2026-07-17  
**状态：** 已批准（方案 A）

## 目标

以 `规航AI-源码-后端联调-20260717/guihang-ai-backend-handoff-20260717` 为唯一视觉和交互基线，在不让旧版页面、组件或数据结构反向污染新界面的前提下，接通现有 FastAPI RAG 服务与 MiniMax-M3，完整验证上传、扫描、结果、路线图、追踪、利润分析和报告下载主链路。

## 已确认问题

1. `feat/handoff-backend-wireup` 已包含 MiniMax 迁移提交和三次前后端联调提交，但集成版相对原始新前端已有 30 个同名文件变化、14 个原稿文件缺失。
2. MiniMax 环境示例已指向 `https://api.minimaxi.com/anthropic/v1` 和 `MiniMax-M3`，但 Docker、Python Settings、Vision 节点及报告生成器仍保留旧 `mimo-v2.5` 默认值。
3. 当前 BFF 只完整适配扫描创建和状态查询；路线图、追踪、报告和资产读取仍有旧本地 session-store 或缺失路由。
4. 后端 `degraded` 状态与前端轮询/跳转状态机不一致，可能让燃烧页永久停留。
5. 结果页会在后端字段不足时静默替换成 Mock 结果，造成真实/演示数据混淆。
6. CSP nonce 与 Next.js 静态页面缓存策略冲突，生产构建可能出现脚本被拦截、页面透明且不可交互。

## 方案

### 1. 新前端是展示层唯一真源

- 原稿中的页面结构、排版、动画、语言切换和视觉资源默认保持不变。
- 只允许为真实状态、错误提示、鉴权传递和数据绑定做最小改动。
- 旧版 Header、旧首页及旧结果视图不得挂载到新主链路。
- 用文件哈希清单和关键页面浏览器截图做视觉回归证据。

### 2. BFF 作为稳定的前端契约层

浏览器只调用 Next.js `/api/*`，BFF 负责：

- 将上传表单转换为 FastAPI `/api/v1/scans` 请求；
- 保存并校验每个扫描会话的 access token；
- 将 FastAPI 状态统一映射为 `processing | ready | degraded | failed`；
- 将后端结果转换为新前端需要的统一 `ScanResult`；
- 代理路线图、Agent Trace、报告和上传资产；
- 将上游超时、未授权、配置缺失和推理失败转成稳定的错误响应。

新前端不直接依赖 FastAPI 的内部字段，也不读取旧本地 Mock session-store。

## 主链路状态机

```text
upload -> create accepted -> processing
                         |-> ready -> result
                         |-> degraded -> result + 明确降级标识
                         |-> failed -> 可恢复错误页
```

- `ready` 和 `degraded` 都是终态，必须离开燃烧页。
- `degraded` 只能展示后端明确返回的降级结果，不能静默替换为前端 Mock。
- `failed` 保留服务端错误码和可安全展示的信息，并允许用户重新上传。

## MiniMax 配置

- 运行时统一采用 MiniMax-M3 的 Anthropic 兼容端点。
- 新增语义清晰的 `MINIMAX_API_KEY`、`MINIMAX_BASE_URL`、`MINIMAX_MODEL`；在一个集中配置边界兼容读取旧 `MIMOTALK_*`，避免一次性破坏已有部署配置。
- 默认端点为 `https://api.minimaxi.com/anthropic/v1`，默认模型为 `MiniMax-M3`。
- Vision 和报告生成器只从集中配置读取，不再各自携带旧供应商默认值。
- Key 只通过测试进程环境注入，不写入仓库、日志、测试快照或构建产物。

## 数据与接口边界

- 扫描创建响应必须返回 `sessionId`、`accessToken` 和初始状态。
- 扫描查询返回统一状态、进度、结果或结构化错误。
- 结果模型明确区分后端实值、后端降级值和缺失值；缺失关键字段时显示不完整状态，禁止伪造。
- 路线图、追踪、利润页和报告下载使用相同 sessionId/accessToken，不产生第二套会话。
- 资产代理校验会话权限、资产索引和内容类型，禁止任意文件路径读取。

## 测试与验收

1. 契约测试：状态映射、结果转换、鉴权、错误映射、路线图/追踪/报告/资产代理。
2. Python 测试：MiniMax 配置优先级、旧变量兼容、Vision/报告生成器共享配置。
3. 前端回归：单元测试、类型检查、ESLint、生产构建。
4. 后端回归：完整 pytest。
5. 真实联调：临时注入用户提供的 MiniMax Key，启动 FastAPI 与生产模式 Next.js，执行真实文件上传并轮询至终态。
6. 浏览器 E2E：验证中英文主页、上传、燃烧页、结果、路线图、追踪、利润页及全部报告下载。
7. 安全检查：无 Key 泄漏、无静默 Mock、无越权会话访问、CSP 下页面可交互。

## 非目标

- 本次不部署生产服务器，不改动线上 `/opt/attrax`。
- 不为追求后端字段一致而重新设计新前端。
- 不在本次迁移中扩展与主链路无关的产品功能。

## 完成标准

- 新前端视觉主线保持原稿，旧版组件不再干扰。
- 有 Key 时真实 MiniMax 主链路到达 `ready`；外部依赖不可用时明确到达 `degraded` 或 `failed`，不死锁。
- 所有主链路页面和下载接口使用同一真实会话。
- 前后端自动化测试、生产构建及浏览器 E2E 给出可复现结果；任何未通过项都有明确风险和复现命令。
