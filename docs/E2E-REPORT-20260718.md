## 4. 失败根因分析

### 4.1 扫描 polling 持续 500 — next.js 16.2.6 jest-worker bug

**错误堆栈(从 next dev fallback 错误页 __NEXT_DATA__ 抓取)**:

```json
{
  "pageProps": { "statusCode": 500, "hostname": "localhost" },
  "err": {
    "name": "Error",
    "message": "Jest worker encountered 2 child process exceptions, exceeding retry limit",
    "stack": "Error: Jest worker encountered 2 child process exceptions, exceeding retry limit\n    at ChildProcessWorker.initialize (D:\\Data\\Desktop\\attrax\\node_modules\\next\\dist\\compiled\\jest-worker\\index.js:1:11580)\n    at ChildProcessWorker._onExit (...)\n    at ChildProcess.emit (node:events:519:28)\n    at ChildProcess._handle.onexit (node:internal/child_process:293:12)"
  }
}
```

**根因**:
- next.js 16.2.6 内部用 `jest-worker` 模块做 server-side bundling / RSC payload 构建
- 该模块通过 `child_process.fork` 创建 worker 子进程做并行编译
- 在 1.6GB RAM + available 429MB 环境下,worker 子进程无法 fork(`ENOMEM` 或 fork 后立即被 OOM kill)
- 反复 fork + fail,触发 "exceeding retry limit" 错误
- next 16 fallback 到 dev mode 错误页(返回 HTML 而不是 JSON API 响应)

**这不是部署代码问题**:本地 `D:\Data\Desktop\attrax` 的 `app/api/scan/[sessionId]/route.ts` 本身正常,只是 next 运行时在 1.6GB 机器上的稳定性边界。

**触发条件**:
- `available < 500MB`(我们 429MB,边缘)
- `swap 0` 几乎没在用
- next 16.2.6 + Turbopack 模式

### 4.2 我自己搞砸的部分(诚实记录)

| 错误 | 原因 | 影响 |
|---|---|---|
| 多次触发 `npm ci / npm install / npm run build` 后台跑 | 同步等回显 / nohup 后台,1.6GB 机器 OOM | 每次 OOM 把 sshd 重新 hang,5+ 次反复 |
| 误判 `next` 目录为空 | 用了 `ls -d`(只显示目录名,没列内容) | 错误触发 npm install,失败 |
| 误删 `.next/standalone` | 不知道 PID 23339 进程独立于磁盘 | 老 nextjs 仍跑但产物消失 |
| chown admin→root 失败 | 权限不允许 | 一次 restore 看似失败(实际 cp 成功) |
| npm ci 后台跑时 SSH channel 占满 | 同步模式,等回显 | sshd 死,5+ 次反复 |

**核心反思**:在 1.6GB 内存约束下,我应该**完全不跑 npm 任何命令**(包括后台 nohup),只做只读 + 已有产物恢复。这个教训我用了 4-5 次 OOM 才学会。

## 6. 后续可选方向(按工作量排序)

### 6.1 立即可做(零额外资源,推荐尝试)

**A. 降级 next.js 到 15.x** — 绕开 16.2.6 的 jest-worker bug
- 改 `package.json` 的 `next: ^15.x` (从 16.2.6)
- `npm install` + `npm run build` 在本地(16GB)做 build
- scp `.next/standalone` + `.next/static` + `public/` + `.env` 上服务器
- `pm2 restart nextjs` 
- **风险**:可能引入 15.x → 16.x 不兼容的 API 差异(本地可能需修代码)
- **预估工作量**:2-4 小时(含测试)

**B. 增加 swap 到 8GB**
- `sudo fallocate -l 4G /swapfile2 && chmod 600 /swapfile2 && mkswap /swapfile2 && swapon /swapfile2`
- 改 `/etc/fstab` 持久化
- 重新 `pm2 restart nextjs`
- **风险**:swap 用上后 jest worker 子进程可能能 fork,但磁盘 IO 抖动 + 整体仍慢
- **预估工作量**:15 分钟

### 6.3 长期(建议)

**D. 拆服务到多 ECS**

- 互不影响
- 扩容灵活
